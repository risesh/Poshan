## Where things live

[`web/`](web/) is the live application (Next.js + Supabase) — all feature work happens
there; see [`web/CLAUDE.md`](web/CLAUDE.md) for what's specific to it. This file only
covers what's shared across the repo: the design system and the design-fidelity source.
The original static-site prototype (`index.html`, `cart.html`, `assets/`, etc.) that
`web/` was migrated from has been removed — it was frozen from the day `web/` was
created and had drifted from what's actually live for weeks before that.

## Design system — always use it, never improvise

The brand's colors, type scale, spacing, and component patterns are documented in
[`Design.md`](Design.md) at repo root. That document is the source of truth for what the
brand looks like.

The enforcement mechanism is [`web/app/tokens.css`](web/app/tokens.css) — a CSS
custom-property file mirroring `Design.md`'s `:root` block exactly.

**Rules for any new page or component in `web/`:**
- Import `web/app/site.css` (which itself imports `tokens.css`) — don't write a new
  standalone stylesheet.
- Never hardcode a brand hex, font-family, or radius. Use the `var(--*)` tokens
  (`--color-ink`, `--color-teal`, `--color-bone`, `--font-display`, `--font-editorial`,
  `--font-mono`, `--radius-card`, etc.) — see `tokens.css` for the full list.
- Before building a new UI pattern, check whether `site.css` already has one (nav, hero
  split, product card, pill/attribute tag, philosophy banner). Reuse the existing class
  before inventing a new one.
- If `Design.md` changes (new color, new type rule), update `tokens.css` to match in the
  same change — they must never drift apart.

## Design reference — the exact source, not a vibe

`design/Poshan Homepage (standalone).html` is the raw export from Claude Design
(claude.ai/design), handed over specifically so this site matches it exactly. Treat every
pixel/color/copy value in it as intentional, not negotiable.

**It is not readable as-is.** It's a self-executing JS bundle (a `.dc.html` "standalone"
export) — the real markup lives inside a `<script type="__bundler/template">` tag as a
JSON-escaped string. Use the decoded, greppable copy instead:

- `design/decoded-source.html` — plain HTML/inline-styles, regenerated by
  `python3 design/decode.py` whenever the standalone export is replaced with a newer one.
  Committed, so it's always available without re-running the decoder. It's a full-funnel
  design canvas — homepage, login/signup, product detail/cart/our story, checkout, order
  confirmation — used as the pixel/copy reference while building the equivalent pages in
  `web/`.
- `design/Poshan Legal Pages.html` / `design/decoded-legal-source.html` — a separate
  Claude Design export/decode pair (same decode mechanism, both entries live in
  `design/decode.py`'s `SOURCES` list) covering only the footer's legal pages: Shipping &
  Returns, Terms & Conditions, Privacy. Built as `web/app/{shipping,terms,privacy}/page.tsx`,
  reusing the real `Nav`/`Footer` components rather than the static nav/footer markup
  baked into the design canvas — only the hero + prose content in between is sourced from
  it (`.policy-hero`/`.policy-content` in `web/app/site.css`).

**Hard rule for any layout/visual value** (padding, margin, width, font-size, color,
copy text): grep it out of `design/decoded-source.html` first. Never estimate a
percentage from a fixed-pixel value, eyeball a screenshot, or rely on memory of a value
read earlier in the session. If a value isn't in the source, say so instead of inventing
one.

**Verify, don't eyeball, after building:** spot-check computed layout against literal
source values (e.g. `el.getBoundingClientRect()` in a headless browser vs. the grepped
px numbers) rather than declaring a section done from a screenshot alone.

## Generated data files

[`Quotes.txt`](Quotes.txt) (repo root) is the human-editable source for the rotating
footer quote. [`build-quotes.py`](build-quotes.py) parses it into `web/lib/quotes.json`
(consumed by `web/app/components/Footer.tsx`). Re-run `python3 build-quotes.py` after
editing `Quotes.txt`; don't hand-edit `quotes.json` — it's strict JSON (no comments
possible to mark it generated), but a hand-edit there gets silently overwritten next
time the script runs.
